# herdr-file-editor

Source of truth for the `file-editor` Herdr app mod (`mods/file-editor/`), published as **File Explorer & Editor**: a dual-mode file explorer panel and tabbed file editor with syntax highlighting, Markdown, SVG, CSV, and XLSX previews, picture zoom, in-editor find/replace, workspace search/replace, and live filesystem watching built natively with GPUI.

## Rule: Always Update the Herdr Live Folder

Herdr reads active mods from `~/.config/herdr-app/mods/<name>`. After code changes in this repository, run:

```sh
./sync.sh
```

The script copies `mods/file-editor` to `~/.config/herdr-app/mods/file-editor` and runs `herdr-app check`. Never edit files in `~/.config/herdr-app/mods/` directly.

## Dual-Mode Architecture

The mod operates in two distinct modes based on whether `props().file` is provided:

1. **Files Pane Mode (`props().file` not set)**:
   - Renders the workspace file browser tree (`#files-tree`) inside `#files`.
   - Resolves workspace root via `resolveLocation` honoring:
     1. Explicit `props().folder` or `props().cwd`.
     2. Pinned space location (`spaces.pinned_locations[space.id]`).
     3. Focused pane or terminal cwd **only when `focused.space === space.id`**.
     4. Fallback to `space.folder`.
   - Polls location in memory every 250ms so switching active spaces or tabs updates the file tree immediately, in addition to the 10s refresh timer and `watchFolder(root)`.
   - **Active Opened File Selection**: Synchronizes with the currently active or focused tab/pane (via `resolveActiveOpenedFile`, checking `focused`, active space tabs, `openTabs`, and `activeFile`). Highlights the opened file with `.bg(t.selected)` and automatically expands and loads any collapsed parent directories (`getAncestorFolders`) so the selected row is always visible in the tree.
   - **Clicking a file (`!entry.dir`) NEVER opens the file inline or replaces the tree**. It invokes `this.openFileTab(path, cx, options)` which checks existing non-settled tabs, reuses matching tabs via `tab.select`, or opens a new dedicated Herdr tab with `tab.new`. When an empty pane (`new-pane`) is present in the active tab, it places the opened file directly into that empty split (replacing the empty chooser pane with `pane.split` and `pane.close`) instead of creating an unwanted new tab or switching away to an existing tab; if the active tab is a lone empty placeholder tab (`space-pin`), it replaces the placeholder cleanly.
   - **VS Code-style preview tabs**: a single click opens the file as a temporary preview (`file-editor.openTabs[fileKey].preview = true`), shown italic and dimmed in the tree and editor header, and dimmed with a hollow dot in the `tabs-ref` tab bar. Double-clicking the file row (`event.click_count >= 2`) or the tab promotes it to permanent. Opening another preview replaces the previous preview tab in the same space (never when it is the last live tab), reuses its strip position, and an edited, pinned, or split preview is promoted automatically before it can be replaced. `planPreviewOpen` in `file-logic.js` owns the replacement decision so it stays unit-tested. The map is keyed by file, not by space: if the same file is opened in two spaces, its preview record follows the latest open and the other tab remains as an independent permanent tab. Never reuse a tab by basename alone; that could focus a different file.
   - Hovering a row tracks it as `hoveredPath` and reveals a copy-path control immediately after the entry name (folders included); it copies the absolute path through `resolveAbsolutePath` and stops propagation so the click never opens the entry.
   - Right-clicking a row opens `#files-context-menu` at the pointer with `Open file` (files only, through `openFileTab`), `Place in empty pane` (when an empty split pane is available), `Copy path`, `Rename`, and `Delete`. The row records the target and the pane root's bubbled press opens the menu from its pane-local `local_position` through `resolveFilesMenuPosition`, which divides by app zoom and flips or clamps the menu inside the panel, and the `#files-context-backdrop` overlay closes it on any outside press. Renaming opens `#files-rename-dialog` with input validation, duplicate checks, and Escape/Enter shortcuts; deleting opens `#files-delete-dialog` with a confirmation prompt before executing filesystem removal and reloading affected tree directories.
   - The header is now a pair of VS Code-style collapsible sidebar sections: `EXPLORER` (the tree above) and `SEARCH`. Each header has a chevron and persists its open/collapsed state in `shared("file-editor.sections")` (`{ explorer, search }`; Explorer defaults open, SEARCH defaults collapsed). `Cmd+Shift+F` / `Ctrl+Shift+F` (also the search icon in the EXPLORER header) expands SEARCH and focuses its query input. The pane root focuses `filesFocusHandle` on any left press so those keys reach the view.
   - **SEARCH section** (`#files-search-section`): a replace chevron sits at the left of the query input, then the query input with `Aa` / `ab` / `.*` toggles, a `…` toggle revealing comma-separated `files to include` / `files to exclude` glob fields, a `N results in M files` summary (with `(limited)` at the caps) and scrollable results grouped by file. Each file header shows a `fileIconPath` icon, base name, dim relative directory and a match-count badge; clicking it collapses that file. Each match row shows its line number and trimmed/ellipsised context around the highlighted span. Clicking a match calls the existing `openFileTab(path, cx, options)` with a `find` option, preserving preview-tab semantics; two clicks inside the double-click window promote the tab. The click carries `find: { query, caseSensitive, wholeWord, regex, line }` as a tab prop and as `shared("file-editor.pendingFind")` so an already-mounted tab can react. `props().search = { query, caseSensitive, wholeWord, regex, include, exclude, replace, replaceOpen, preserveCase }` opens the pane with a prefilled search and optional replace row; `search.replaceDialog: true` (with `replaceOpen: true`) only opens the Replace All confirmation for the settled results and never writes.
   - **Replace in files**: expanding the replace chevron shows a replace input, an `AB` preserve-case toggle and a Replace All button (disabled with no results). With the row open, every match row previews the VS Code inline diff: the match struck through on a red tint followed by the expanded replacement on a green tint (newlines/tabs become `↵`/`→`). Hovering a match row reveals Replace and Dismiss; hovering a file header reveals Replace All in file and Dismiss. `Cmd+Shift+1` / `Ctrl+Shift+1` replaces all only while the replace row is open and results exist. The SEARCH Replace All button and shortcut always open `#files-replace-dialog` with `Replace N occurrences across M files with 'X'?` and Cancel/Replace, even for one match or one file; the per-row Replace and per-file Replace All hover actions write directly. Writes check the real file size first and skip files at or above 1 MiB (`too large`) or reads containing `\uFFFD` (`not UTF-8`), re-read each file, recompute matches with the same options and apply only targets that still match at the same line/column/length. Files changed on disk, unreadable files and files with unsaved editor edits (live, cached or sessionStorage) are skipped and reported with their reason in the toast. Writes use `writeTextFile` / `writeRemoteTextFile` with the fresh text as the expected snapshot, so line endings, the trailing newline and a UTF-8 BOM survive. After the run the search re-runs and replaced rows disappear.
   - Results are manually windowed (visible rows plus six rows of overscan) rather than a `v_virtual_list`, because GPUI refuses event handlers inside a virtual-list renderer and the hover actions need per-row handlers. `searchWindow` owns the math; for 2,000 results in a 400px viewport at 24px rows at most 29 rows render per frame.
   - Searches are debounced by 300ms, run in `cx.spawn` off the UI thread, and use a per-search token (`searchToken`) so stale scans are discarded, matching the `watchToken` pattern. `rg --json` is used when `rg --version` succeeds (which honours `.gitignore`); otherwise the mod falls back to `grep -rn` and re-runs the pure match engine over each candidate line. Both paths apply include/exclude globs and cap at 2,000 matches / 200 files.


2. **File Editor Tab Mode (`props().file` is a non-empty string)**:
   - Renders a full-size file editor tab (`#file-editor-tab`) for `{ folder, file, on?, viewMode?, wrap?, zoom? }`.
   - Reads file text via `readTextFile` off the UI thread and watches `root` via `watchFolder` so external edits reload automatically without clobbering unsaved dirty changes.
   - Header bar (`h(38)`, `bg(t.chrome)`) provides:
     - Basename with an accent dot indicator (`●`) when unsaved edits are present, italic while the tab is a temporary preview, copy path button, truncated parent path, line count & language pill, and an icon action group with uniform 24px alignment:
     - `Save` icon button (`save.svg`, accent-highlighted when dirty, supporting Cmd/Ctrl+S with descriptive tooltips) or a `Read-only` lock icon indicator (`lock.svg` with reason tooltip).
     - For Markdown files (`.md`, `.markdown`, `.mdx`), CSV/TSV tables (`.csv`, `.tsv`) and SVG files (`.svg`): segmented `Preview` (eye icon) / `Code` (brackets icon) view switcher defaulting to `"preview"`. In Code view, full text editing and saving are supported.
     - For XLSX/XLSM workbooks (`.xlsx`, `.xlsm`): a preview-only table with worksheet tabs, read-only semantics, and no Code toggle because the workbook is binary.
     - For raster images and SVG previews: zoom controls (`−`, percentage, `+`), a reset-to-fit percentage button, and Cmd/Ctrl + wheel zooming. Zoom runs from 25% to 400%; 100% fits the picture to the pane and larger levels scroll in both directions.
     - In Code view: `Wrap` icon toggle button (`wrap.svg`, and `Alt+Z` / `Opt+Z` keyboard shortcut) toggling soft wrapping on `EditorState` and persisting to `shared("file-editor.wrap")`.
     - `Split right` and `Split down` icon buttons (`split-right.svg`, `split-down.svg`, and `Cmd+\` / `Ctrl+\` keyboard shortcut) splitting the editor pane with `new-pane` chooser (or terminal if `new-pane` is missing).
     - Copy button next to the file name writing current text to the clipboard with a toast notification.
     - Refresh button (`refresh.svg`) reloading from disk and discarding uncommitted edits; automatic background watcher (`watchFolder`) and 1.5s disk change poller update files live when modified by agents, git, or external processes without clobbering dirty edits.
     - Find button (`search.svg`) opening the in-editor find widget. `Cmd+F` / `Ctrl+F` and `F3` / `Shift+F3` do the same; the native `Editor` consumes the Cmd+F key press in its own `input::Search` binding, so the tab also opens find from `on_key_up` (`handleKeyUp`). A new file tab takes the keyboard automatically (editor in Code view, view root in previews) so the shortcut works without clicking the text first. The widget is docked top-right over the content with a focused query input, `Aa` / `ab` / `.*` toggles (Alt+C / Alt+W / Alt+R), an `N of M` counter (or `No results` / `Invalid regex` with a red input border), previous/next buttons and close. `Enter` / `Shift+Enter` step with wrap-around; `Esc` returns to the native Editor.
     - **Replace row**: a chevron at the left of the find bar expands a second VS Code-style row with a replace input, an `AB` preserve-case toggle, Replace and Replace All buttons. `Cmd+Alt+F` / `Ctrl+H` opens find with the row expanded; the expanded state, last replace text and preserve-case flag persist in `shared("file-editor.find")`. While the replace input is focused, `Enter` replaces the current match and moves to the next; `Cmd+Enter` / `Ctrl+Alt+Enter` replaces all; `Cmd+Shift+1` also replaces one and `Cmd+Alt+Enter` replaces all. Replacements edit the buffer through `this.code.set_value` only (nothing is written until save), mark the tab dirty, promote preview tabs and keep a small in-memory undo stack so `Cmd+Z` / `Ctrl+Z` while find is open restores the text before the last replace. Buttons are disabled with a read-only tooltip on protected files.
     - While find is open the tab renders a read-only virtualised text view (`find-view.js`) instead of the native `Editor`: GPUI's `EditorState` exposes only `value`, `set_value`, `on` and `release`, with no selection, cursor, scroll-to-line, focus or decoration API, so the mod owns matching and highlighting. The view uses the same 13px code font, 20.5px line height, and a line-count-based gutter width as the editor, so opening find does not resize or shift the code. It keeps the file's syntax colors through `tokenizeCodeLines` (`file-logic.js`), a pure lightweight tokenizer for JS/TS, JSON, CSS, HTML/XML, Markdown, Rust, Python, Go, C/C++, Java, Kotlin, Swift, PHP, Ruby, Lua, Bash, YAML/TOML, SQL, Dockerfile, Makefile and CMake; block comments, template literals and triple-quoted strings carry state across lines. `refreshFindMatches` caches the tokenized text in `this.findSyntax` (keyed by source text and language) so typing a query does not re-tokenize on every keystroke. All matches get a highlight and the current one is scrolled into view through a `VirtualListScrollHandle`; only visible lines are rendered. The native `EditorState` in `this.code` is never recreated or `set_value`'d by opening/closing find, so unsaved edits, cursor and undo state survive. Editing pauses while find is open, as accepted. Markdown/SVG previews switch to Code view when find opens (the read-only view is the only surface that can bring a match into view; documented behaviour). Images have find disabled.

   - Code editing and rendering uses `EditorState.new` with syntax highlighting from `theme()` and font settings. Listens to `change` events for real-time dirty tracking and Cmd/Ctrl+S saving via `writeTextFile` (locally) or `writeRemoteTextFile` (remotely over SSH via `herdr-core` `exec`).
   - **Scroll and View Position Preservation**: Preserves the user's position (scroll, cursor, selection, view mode, zoom, and unsaved edits) across tab switches, view mode toggles, and reopens. Retains active file editor state in a bounded LRU cache (`fileTabStates`), restores cached content immediately on frame 1 to prevent 0-height scroll resets, and assigns deterministic, per-file GPUI element IDs (`fileElementId`) to Editor, Markdown, and picture view containers. Because GPUI's element state manager sweeps ephemeral layout scroll offsets for views unmounted during frame rendering of other tabs, preview scroll and pan offsets (`mdScrollY`, `pictureScrollX`, `pictureScrollY`, `sheetScrollX`, `sheetScrollY`, `activeSheet`, `tabViewport`) are tracked directly in memory on the view instance, persisted in `fileTabStates` and `sessionStorage`, and applied through offset positioning (`.top(-mdScrollY)`, `.left(-pictureScrollX).top(-pictureScrollY)`, `.top(-rows.offset).left(-columns.offset)`) paired with smooth proportional scrollbars, guaranteeing that switching tabs or spaces always restores the exact scrolled position.
   - Markdown rendering is GitHub-style and built in `mods/file-editor/markdown-view.js`: `parseMarkdownBlocks` (file-logic.js) turns the source into blocks, which are drawn as headings with rules, code boxes, bordered tables, quote bars, list and task markers. Inline text (emphasis, code, links) goes through `TextView.markdown`, which takes no styling of its own.
   - Spreadsheet previews live in `mods/file-editor/spreadsheet.js`: CSV/TSV parsing honors quoted fields, escaped quotes, CRLF, newlines inside quotes, and BOMs, and auto-detects comma/semicolon/tab delimiters. XLSX/XLSM is read directly from its ZIP container (`zlib.inflateRawSync`) without a third-party dependency: shared strings, workbook relationships, worksheet order, cell styles, dates, percentages and inline strings. The table has a sticky header, sticky row-number gutter, worksheet tabs, per-sheet scroll restoration, and row virtualization. Both formats cap the preview at 2,000 rows × 100 columns and 500 characters per cell; a footnote appears when a limit is hit. Workbooks are transported through `exec` + base64 because `fs.readFile` is capability-gated; `herdr.exec` caps stdout at 8 MiB, so a workbook beyond that budget shows a friendly notice.
   - Picture previews use `imageHeaderSize` (raster header parsing) and `prepareSvgPreviewInfo` (SVG root size) to know the picture's aspect ratio. With the pane measured from pointer/wheel bounds, `renderPictureCanvas` sizes it in pixels for an exact fit; before that, a percentage aspect box fits by width using `padding-top` relative to the box width. The preview is top-left aligned when zoomed in, centered at fit, and wrapped in `overflow_scrollbar` for panning; `file-logic.js` owns the level ladder (`IMAGE_ZOOM_LEVELS`, `normalizeImageZoom`, `stepImageZoom`, `imageZoomPercent`).
   - SVG preview writes an enlarged copy of the source into `cache/file-editor/` and draws it with `image()` on a light canvas. The host rasterizes SVG at the root `width`/`height`, so `prepareSvgPreview` (file-logic.js) scales the intrinsic size up while preserving the `viewBox`; the light canvas keeps `currentColor` icons visible on dark themes. The cache copy is refreshed on reload and removed in `close(_cx)`.

## Find & Workspace Search Architecture

- **In-editor find (`find-view.js`, `find-logic.js`)**: `Cmd+F` / `Ctrl+F` (on key release) and `F3` / `Shift+F3` open `#file-find-widget` while the editor is focused. Current Herdr's native `Editor` handles `input::Search` itself and stops the key press before GPUI's keymap, so `handleKeyUp` opens the widget from the release; the key-down bindings still cover previews and hosts that do not shadow the chord. New tabs focus the editor (or the view root in previews) so the shortcut works immediately. The app-wide action bindings are installed once per process by `ensureFileEditorKeyBindings` (guarded on `globalThis`), not from every tab/pane init. The widget owns the query, toggles, current index and matches on the view (`this.find`), while the pure engine (`findMatches`, `buildFindRegExp`, `stepMatchIndex`, `findMatchIndexAtLine`, `lineMatchSegments`) lives in `find-logic.js`. Regex mode uses the `m` flag so `^`/`$` anchor at every line; whole-word uses boundary groups with a capture and lets the engine backtrack through alternations (`foo|foobar`). The read-only view slices the line at the current match column when it would be off-screen. The last query and toggles persist in `shared("file-editor.find")`. Invalid regexes are reported as data (`{ valid: false, error }`), never thrown. Editing is paused while find is open, and the native `EditorState` is left untouched so unsaved edits survive. Images disable find. Markdown/SVG previews switch to Code when find opens.
- **Key contexts**: `Escape` is bound only in `FileEditorFind`, which the find bar declares, so it cannot swallow Escape while find is closed. `F3`/`Shift+F3` live in `FileEditor`; when find is closed they call `stepFindOrOpen`, opening with the last query first. `Cmd+F` / `Ctrl+F` are also GPUI bindings, with `handleKeyUp` as the fallback the native editor cannot consume; `Cmd/Ctrl+G` and `Cmd+Alt+F` / `Ctrl+H` are bound too, but the native editor can consume the unmodified Cmd/Ctrl chords first. Root mouse-down handlers focus the view only when no native editor is shown (previews), not in Code view, so they never steal focus from the editor or the search inputs; the Files tree focuses `filesFocusHandle`.
- **Replacement engine (`find-logic.js`)**: `expandReplacement` implements VS Code replacement semantics: plain mode inserts literally; regex mode supports `$0` / `$&` (the whole match), `$1`..`$99`, `$$`, `\n`, `\t`, `\\`, `\$` and the `\u` / `\l` / `\U` / `\L` / `\E` case operations; unknown escapes keep their backslash, so `C:\path` survives. `applyPreserveCase` follows VS Code's `buildReplaceStringWithCasePreserved`: all-upper → upper, all-lower → lower, mixed case adjusts only the first letter, and hyphen/underscore-separated segments are handled per segment when the counts match. `applyReplacements` works back to front, skips overlapping matches, keeps untouched text byte-identical (so CRLF, a trailing newline and a UTF-8 BOM survive) and recomputes capture groups once from the query for `$1` support. `replaceSingleMatch` replaces one match, re-runs the query and selects the first fresh match at or after the inserted text (wrapping), so a replacement that still matches is not selected immediately. `replacementDiffSegments`, `expandSearchReplacement`, `selectFreshMatches`, `planFileReplacements`, `collectReplaceTargets`, `formatReplaceAllConfirmation`, `classifyReplacementRead` and `isDirtyFileState` keep the SEARCH diff and safe file-write rules pure and unit-tested.
- **In-editor replace**: `replaceCurrentMatch` / `replaceAllInEditor` call `this.code.set_value`, then update `preparedText`, `dirty`, `lineCount` and the tab cache; nothing touches disk until `saveFile`. Replace All recomputes matches with an unbounded cap, so it is not limited to the 5,000-match display cap. The in-memory `findUndo` stack (bounded to 50) stores `{ text, current }` snapshots because `set_value` may reset native undo; `Cmd+Z` / `Ctrl+Z` while find is open restores the last snapshot, and the chord is only consumed when the stack is non-empty so input undo still works otherwise. Replace is disabled for read-only files (binary, image, truncated or unreadable) with the existing read-only reason in the tooltip. Replace chords require the replace row to be open. Props may set find UI state but never trigger a replacement.
- **Find prop once**: a tab `find` prop is applied once per file. `findPropSignature` (query/toggles/line plus replace text/expanded/preserve-case) is stored in the per-file cache and sessionStorage, so remounting a tab with the same props does not reopen find. Search-result handoffs use `shared("file-editor.pendingFind")`, which is cleared when consumed and ignored after `PENDING_FIND_TTL_MS` (15s).
- **Search results (`renderSearchSection`)**: the sidebar renders both sections; SEARCH state lives on the view (`this.search`, `this.searchRows`, `this.searchToken`, `this.rgAvailable`) and results are a flat row list built by `flattenSearchRows`. GPUI forbids handlers inside a virtual-list renderer, so the list is manually windowed: `searchWindow` returns the visible rows plus six rows of overscan, the view owns `searchScrollY`/`searchViewportHeight`, and only those rows are built with normal per-row hover/click handlers. For 2,000 results in a 400px viewport at 24px rows that is at most 29 rendered rows. Parsing (`parseRgJson`, `parseGrepOutput`, `expandGrepRows`), globbing (`parseGlobList`, `globToRegExp`, `matchesGlob`, `searchGlobVariants`, `filterSearchRowsByGlobs`), command args (`buildRipgrepArgs`, `buildGrepArgs`), exit-code policy (`classifySearchResult`), grouping/capping (`groupSearchRows`) and summaries (`formatSearchSummary`) are pure and unit-tested. Bare names such as `src` match that node at any depth (`**/src/**` and `**/src`). The query is passed to the tools untrimmed; only a whitespace-only query is treated as empty. Glob filtering happens before the 2,000-match cap in the grep path.
- **Replace in files (`runFileReplacements`)**: the SEARCH Replace All button and `Cmd+Shift+1` always open the confirmation dialog, even for one match or one file; the per-row Replace and per-file Replace All hover actions run directly. Actions require the replace row to be open. Targets are snapshotted by file from the current groups. Each file's real byte size is checked first (`fileByteSize` with `sh wc -c` or PowerShell, same `on`); files at or above 1 MiB are skipped as `too large` because `readTextFile` caps at 1 MiB. The fresh read is rejected if it contains `\uFFFD` (`not UTF-8`), and dirty editor state is re-checked after the await. `planFileReplacements` re-runs the query and applies only targets whose line/column/length still match; any missing target skips the whole file as changed. A UTF-8 BOM is preserved, and line-1 columns are offset by one to match rg's BOM-stripped output. Unsaved edits are detected through `dirtyFileKeys`, the bounded cache and sessionStorage (a closed tab can be restored from the cache with its dirty buffer), with keys normalized by `toFileKey`. Writes use `writeTextFile` / `writeRemoteTextFile` with the fresh text as the expected snapshot. The run then shows `Replaced N occurrences in M files (K skipped: file (reason))` and re-runs the search. Props may open the dialog (`search.replaceDialog`) but never run a replacement.
- **Bounds and failures**: rg runs with `--max-columns 1000 --max-columns-preview --max-filesize 1M --max-count 200`; grep uses `-I --null -m 200` plus `.git`/`node_modules` exclusion and pre-cap glob filtering. Both get a 20s `exec` timeout. `exec` has no cancellation handle, so superseded scans are ignored via `searchToken`. Exit 2 keeps parsed matches and shows a dim warning (`classifySearchResult`); only a run with no rows becomes an error. Regex dialect failures are cleaned by `formatSearchError` (`Regex not supported by search: …`); the grep fallback uses POSIX ERE.
- **Opening a result**: `openFileTab` carries `find` through tab props; for an already-open tab it writes `shared("file-editor.pendingFind")`, which `syncTabConfig` consumes. The `line` is 1-based in the prop/search row and converted to the engine's 0-based line before selecting the first match at or after it.
- **Known remote-write limitation**: `writeRemoteTextFile` writes a temp file and `mv -f`s it over the target, which may drop the target's file mode. Copying the mode portably (`chmod --reference` is not portable) is not done; the limitation is documented here and in README.

## GPUI Invariants & Safety Rules

- **No `null` or `undefined` in `.child()`**: Re-rendering aborts with an error banner if null/undefined is passed to `.child()`. Always use `.when(cond, el => el.child(...))`.
- **No sync `cx` across `await`**: Event handler `cx` is valid only during synchronous delivery. Wrap all async tasks in `cx.spawn(async (cx) => ...)` and use the `AsyncContext`.
- **Never call `EditorState.new` inside `render()`**: Editor instances must be created or updated outside `render()` (in `loadFile` or event handlers). Always call `this.code?.release()` before recreating or in `async close(_cx)`.
- **Watch tokens**: Always use a per-loop `watchToken = {}` so changing directories or files invalidates stale watchers. Clear `watched` and `watchToken` in `close(_cx)` or when switching context.

## Validation & Testing

Run the automated test suite and mod validator:

```sh
herdr-app check mods/file-editor && node --test test/
```

- `mods/file-editor/file-logic.js`: Pure functions for path splitting, language detection, view mode defaults, file text preparation, SVG preview preparation (`prepareSvgPreview`, `prepareSvgPreviewInfo`), raster image dimensions (`imageHeaderSize`), picture zoom levels (`normalizeImageZoom`, `stepImageZoom`, `imageZoomPercent`), Markdown block parsing, syntax theming (`buildSyntaxTheme`, `tokenizeCodeLines`), location resolution, tab resolution, file icon choice (`fileIconPath`), spreadsheet file classification (`spreadsheetKind`, `isCsvFile`, `isXlsxFile`), and Files context-menu placement (`resolveFilesMenuPosition`, zoom-aware so the menu stays under the pointer). Icons in `mods/file-editor/icons/` are full-color SVGs from Material Icon Theme (MIT, license in `icons/LICENSE.txt`), drawn with `image()` so their colors survive; `svg()` would tint them with the text color.
- `mods/file-editor/spreadsheet.js`: Pure CSV/TSV and XLSX/XLSM parsing plus table geometry (`parseDelimitedText`, `parseXlsxWorkbook`, `visibleColumnRange`, `visibleRowRange`), testable in Node and independent of GPUI/Herdr.
- `mods/file-editor/find-logic.js`: Pure find/search/replace engine: literal/regex/whole-word/case query building, match scanning with line/column ids, counter labels, step-with-wrap, query → line lookup, line highlight segments, syntax/match segment merging (`mergeSyntaxSegments`), context trimming, glob parsing/matching, rg JSON and grep output parsing (including astral/CJK byte offsets and BOM normalization), grep re-matching, grouping/capping, sidebar sections, find props, replacement expansion (`expandReplacement` with `$0` and backslash-preserving unknown escapes), preserve case (`applyPreserveCase`), back-to-front application (`applyReplacements`), single replace + next selection (`replaceSingleMatch`), inline diff segments, safe file-replace planning (`planFileReplacements` with BOM handling, `selectFreshMatches`, `collectReplaceTargets`), read safety (`classifyReplacementRead`), dirty-state safety (`isDirtyFileState`), windowing (`searchWindow`) and confirmation text.
- `mods/file-editor/find-view.js`: GPUI rendering for the find bar and replace row, the virtualised read-only match view and the SEARCH sidebar section (replace row, inline diff, hover actions, manual windowed results).
- `test/file-logic.test.js`: Unit tests verifying contract, edge cases, and boundaries with `node:test` and `node:assert/strict`, including the find-view syntax tokenizer (`tokenizeCodeLines`) and its cross-line state.
- `test/spreadsheet.test.js`: CSV quoting/delimiter/cap tests, XLSX fixture coverage (ZIP + shared strings + styles + sheet relationships), and virtualization geometry tests.
- `test/find-logic.test.js`: Unit tests for the match engine, regex builder, globs, rg/grep parsing, grouping/capping, counter/step/wrap, context trimming, syntax/match segment merging, search props, replacement expansion, preserve case, CRLF/unicode/adjacent/overlapping replacement, single-match next selection, inline diff segments, safe file-replace planning, read-safety classification, dirty-state detection, search windowing, astral/CJK/BOM handling, >5,000-match replacement and confirmation text.

## Layout Wiring

To replace the default `files` panel block in your personal layout clone (`~/.config/herdr-app/layouts/<name>.json`):

```json
{
  "id": "files",
  "type": "block",
  "content": {
    "mod": "file-editor"
  }
}
```

### Direct Split and Tab Commands

Open the Files browser in a side split:
```sh
herdr-app do pane.split --direction right --mod file-editor
```

Open a specific file directly in a dedicated tab:
```sh
herdr-app do tab.new --name "README.md" --mod file-editor --props '{"folder":"/path/to/repo","file":"README.md"}'
```

Open a code file with soft wrap enabled:
```sh
herdr-app do tab.new --name "main.js" --mod file-editor --props '{"folder":"/path/to/repo","file":"src/main.js","wrap":true}'
```
